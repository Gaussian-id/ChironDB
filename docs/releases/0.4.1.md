# ChironDB 0.4.1

Release-pipeline fix on top of 0.4.0. The server, storage and API behaviour
are unchanged; every change listed in the [0.4.0 release notes](0.4.0.md),
including the RT-11 breaking change, ships for the first time in this release.

`v0.4.0` was tagged but never published. Its release run stopped before any
build, so no 0.4.0 binaries, container image or GitHub release exist. 0.4.1 is
the first published release on the plain `x.y.z` line.

## Release pipeline

### The encrypted SIFT gate has its own job and budget

The WAL release gate ran the plaintext and the encrypted SIFT-128 benchmarks
in one job with a 120-minute limit. The encrypted step alone took 56 minutes
on a normal runner, and on a slower runner the `v0.4.0` run hit the limit
while that step was still running.

An A/B on 1M × 128 vectors found no regression in the encrypted path between
0.1.0-beta.3 (`0bd6f5d`) and 0.4.0 (`c956d7c`): 3465 s and 3473 s, with
the same search rate, memory and bytes on disk. The time limit was simply too
tight for the encrypted run.

The gate is now three jobs:

| Job | Runs | Budget |
| --- | --- | --- |
| `wal-release-gate` | plaintext recall and recovery | 120 min |
| `wal-encrypted-release-gate` | encrypted recall and recovery, in parallel | 240 min |
| `wal-encryption-overhead` | the encryption overhead check, on both results | 15 min |

The gate arguments and thresholds are unchanged, and the combined
`wal-sift-release-gate` evidence artifact is still uploaded. Builds start only
after all three jobs pass.

## Known limitation

Encrypted vector search is about 6x slower than plaintext, and the gap grows
with collection size. It is tracked as separate performance work.
