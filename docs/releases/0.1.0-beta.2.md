# ChironDB 0.1.0-beta.2 — evaluation preview

This source update adds the implemented native relational database alongside
vector search, BM25/hybrid retrieval and the property-graph overlay. It is
**not production ready**. All features are for evaluation while compatibility,
security, resource, recovery and release acceptance remains open.

## Relational surface

Typed SQL tables, constraints, scalar indexes, transactions/savepoints, aggregates
and bounded equijoins are implemented. Use the documented SQL subset through
ChironQL `SQL`, HTTP, gRPC, ChironWire or the native PostgreSQL wire profile.
The legacy pgvector profile keeps its six vector-only shapes and existing
`0A000` rejections. Native SQL does not promise full PostgreSQL/ORM compatibility.
The documented non-recursive CTE/subquery subset is supported; recursive,
correlated and lateral queries remain unsupported. See [ChironQL](../CHIRONQL.md) and
[getting started](../GETTING_STARTED.md#postgresql-and-pgvector-boundary).

## Terminal output and model availability

Unavailable SQL/JSON values display as `NULL` in console/client tables. Empty
text remains empty; JSON retains `null` and stored data is unchanged.
TabFM integration and weights are excluded because the project does not have
required model usage rights. No foundation-model fine-tuning capability is shipped.

## Compatibility and validation

Existing compatibility names are retained. Protected installation migrations
and reader fences are explicit offline operations; read the applicable migration
runbook before upgrading existing data. Keep complete journals and recoverable
backups. Do not treat this preview as a production durability or uptime guarantee.

Versioned binaries/images should be used only when verified artifacts exist.
This release note describes the candidate source, not a claim that required
remote CI, release signing or binary publication has completed.

## Traditional ML evaluation

Decision Tree and Random Forest support classification and regression through
`ML MATERIALIZE`, HTTP job/result routes and both SDKs. The optional Python
worker is provisioned separately; no foundation-model weights are included.
Use [the worker setup](../../ml-worker/README.md) and `./scripts/chiron-ml`
for a single server and interactive console. ML is unavailable with protected
tenant enforcement. Regression confidence is `NULL`; classification confidence
is a selected-class probability, not measured accuracy.

Legacy ChironWire health probes remain available when data-work admission is
saturated. Authentication, authorization, rate limiting and audit remain enforced;
data queries retain their existing resource limits.
