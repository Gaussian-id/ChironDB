# ChironDB 0.1.0-beta.3 — evaluation preview

This source version adds recovery checks and durable bulk loading for documents,
vectors, SQL rows and graph relations. ChironDB remains an evaluation preview.
Use tagged binaries and container images only when their signed artifacts are
available and verified.

- Startup refuses a catalogued collection with missing required WAL segments.
  Interrupted offline key rotation also blocks startup and can be resumed with
  the complete keyring before retiring an old key.
- Encryption migration handles compacted legacy generations and retained WAL
  archives. Startup reclaims recognized unpublished atomic-write staging files
  under the exclusive storage lock; authoritative corruption still rejects.
- Online graph compaction preserves durable WAL tails appended during sealing,
  including graph-handle backfill. Offline encryption preparation still refuses
  a nonempty tail and succeeds when retried after concurrent writers stop.
- Atomic relation batches use one collection, ordered edge IDs, one commit
  receipt and a stable batch idempotency key. HTTP, gRPC and ChironWire share
  the same scoped engine. Existing single-edge APIs remain compatible.
- The [bulk loader](../BULK_LOADING.md) uses reused connections, bounded queues,
  batches of 50, durable commits and resumable client checkpoints. It reconciles an
  ambiguous edge/SQL ACK with its original key before retrying.
- Bulk SQL writes wait for active checkpoints under retained-memory pressure.
  Reads and committed batch replay remain available. Live graph point updates
  now publish text-index statistics once, preserving retrieval across restart.
- Independent Rust, Python and JavaScript SDK repositories replace the bundled
  clients. Their qualified revisions remain pinned separately from this server
  version; [SDK integration](../../sdk-integration/README.md) requires trusted
  repository-read credentials in CI. Building the server requires no SDK token.

## Upgrade

Back up the installation and complete any pending offline key rotation before
upgrading. Writable WAL metadata upgrades from `GAUSSWB1` to CRC-protected
`GAUSSWB2`, recording the retained prefix and required final segment. Immutable
archives remain unchanged. Older binaries reject the new metadata; downgrade
requires a verified pre-upgrade backup. A suffix already lost before this
upgrade cannot be reconstructed. Do not create empty replacement WALs or delete
metadata to bypass a recovery error.

The existing snapshot-v3 checksum fix and explicit verified legacy-snapshot
converter remain available. See [snapshot compatibility](../SNAPSHOTS.md) and
[storage migration](../GETTING_STARTED.md) before moving persisted data.

## Qualification

The corrected OSS source passes the macOS ARM64 and Linux ARM64 workspaces and
strict lint, full serial fault injection, and 1,000 plaintext plus 1,000
encrypted physical crash/restart cycles. Deterministic tests cover concurrent
graph tails during initial sealing and compaction, plus offline migration
refusal and retry. The four pinned-nightly WAL fuzz corpora each complete 256
ASAN executions on Linux ARM64.

The preceding combined candidate also passed release builds, three-protocol
startup/restart checks, an anonymous product build without SDK credentials,
all 20 pinned standalone SDK stages, and 45 audited MCP outcomes. Its public
CI passed the main and security workflows, including trusted SDK integration.
Fresh local anonymous-build, SDK and MCP repetitions, and additional pre-tag
qualification are deferred for this evaluation preview. Those historical
results are not represented as final-revision results.

The incoming engine's primary ingest fixture reconstructs 5,183 SciFact documents
and 15,545 synthetic edges. Five matched alternating runs at batch 50/concurrency
8 produced median readiness times of 3.800 seconds for ChironDB and 4.736 seconds
for SurrealDB 3.3.5 (ratio 0.802). The 10x diagnostic remained slower at ratio
1.473. These measurements do not reproduce the unavailable historical P4 script
or establish a general performance ranking.

Official full SIFT-128 on the incoming engine reaches recall@10 of 0.98052 in
both plaintext and encrypted modes. All 300 SciFact query rankings are preserved
across restart. Official SIFT/recovery remains part of the tag-triggered release
workflow.

Protected branch checks and automated release jobs remain enabled. Local
results do not certify an unpublished artifact.

The project remains AGPL-3.0-only. Linux and macOS x86-64/ARM64 are the required
binary targets; Windows follows the existing best-effort policy.
